自动寻路与AI接口验收

2026年11月11日 · 打开游戏

静决定引导目标，程序按当前场景计算路线。默认目标仍为一层108东端亮门；AI可以查询房间、门前或指定楼层坐标。寻路不会控制玩家行走，也不会擅自改门、拆墙或移动物体。

接口与返回信息

find_path { room: "108" }
find_path { door: "D110" }
find_path { floor: "1F", x: 38.5, z: 24.5, allow_locked: false }

返回目标、当前位置、朝向、可达状态、距离、下一步绝对方位、指南针角度、相对左右、经过的门，以及开门、解锁、等门或乘梯的前置步骤。默认锁门会挡路；allow_locked:true仅允许规划“先解锁”的条件路线，仍不实际开锁。

每轮感知附带当前目标的实时navigation；选新目标时可以调用find_path。查询轮先读取结果，之后再生成台词，查询中的临时猜测和其他改造不会提前执行。普通对白继续等待前句语音结束。

路线使用0.5米水平采样、真实站立高度与0.3米碰撞半径，检查地面支撑及跨步过程；沿可直接行走的视线合并小格，避免每半米停一次。只有当前下一步给出相对朝向，后续步骤使用绝对方位，并在下一轮重算。

实际AI调用

路线确认好了。请转身朝东北方向，大约54度，走七八米到那扇玻璃门前，到了再问我。

验证了两种流程：直接使用每轮提供的navigation；以及未预送navigation时，模型先调用find_path，前端计算并反馈，再由模型给出上述台词。后一流程使用了2次模型请求，实际执行工具记录包含find_path。
