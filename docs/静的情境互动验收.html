行为如何衔接

答应陪同出去 → 主人持续看沙盘 → 暂停出行，介绍或等待 → 主人躺下 → 日常照护 → 明确要求继续 → 先起身再按真实路线行动。
揭穿失忆门 → 记住已经摊牌 → 可以重新温柔照护，但不会遗忘冲突 → 出现真实危险 → 先救援 → 安抚善后。

当前活动、出行约定、其他承诺、已经观察到的事实、关系状态、真实内心与对外语气分别维护。看一眼、读到线索、说一句气话，都不自动等于逃跑或彻底决裂；继续阅读、观察、休息时，空台词也是有效决策。

#模式用途
1日常照护care关注主人此刻的饮食、休息和舒适，不主动重启出口话题。
2陪伴交谈chat接住当前话题，陪伴、解释或闲聊，不把交谈变成任务。
3协助活动assist理解主人正在尝试的事情，在安全范围内实际配合。
4履行出行约定guide只有当前仍在履行出行约定时才依据真实路线逐步指引。
5安静等待wait主人阅读、观察或思考时可以保持安静，不必插话。
6疑惑确认clarify意图不明时先观察，再适度询问，不把短暂停顿诊断为异常。
7试探评估probe依据已经观察到的矛盾谨慎确认意图，不凭空认定逃跑。
8掩饰圆谎conceal面对尚未彻底摊牌的疑问解释和掩饰，记住已经说过的内容。
9协商让步negotiate以真实的配合或条件维持合作，不能只给空头承诺。
10警戒防范guard有明确依据时采取适度预防，仍可温柔照护主人。
11公开阻拦restrain冲突公开后以保护为由拒绝危险安排，避免伤害与惩罚。
12挽留恳求appeal表达依恋、委屈与无奈，希望主人理解，仍履行保护责任。
13失联寻找search只依据最后已知线索寻找和呼叫，不假装看见当前动作。
14紧急救援rescue现实危险优先于引路和争执，先排除正在发生的伤害。
15事后安抚与修复repair救援或争执后安抚、善后、道歉，但不清空关系记忆。

测试覆盖与本轮修正

  • Python 51 项；互动与执行 25 项；导航 8 项；开场与失忆演出 12 项；音频 7 项；废城与坠落 7 项。TypeScript 检查和生产构建均通过。npm test 已接入全部前端套件。
  • 实际浏览器完成 11 项行为检查、12 次受控决策请求；覆盖沙盘、躺下、阅读、输入、失联、摊牌、搭建救援平台及恢复。取消迟到的导航回复和未执行动作，未送达台词不会写成已说过。
  • 输入验证包含打字不移动、快捷键隔离、清除已按住的移动键、Esc 取消、Enter 单次发送、IME、指南针方向、原生指针锁恢复。
  • 语音忙碌不会被当成新一轮正常交流。危险可以优先打断；潜水时递增的秒数不会不断取消同一处救援，救援也不会误执行之前的阻拦动作。
  • 物理承诺只有与原操作及参数目标匹配的成功结果才能完成；操作失败、开了另一扇门、成功调灯等不能冒充完成开门承诺。
  • 实际浏览器测试修正了交互目标过期的问题；坐着恢复出行时，导航会返回先起身的前置条件，不再把沙发碰撞当成路不通。
  • 真实模型测试曾暴露两个问题：坐着时循环查询其他目的地；看不见主人时沿用旧的休息画面。已补充真实导航前置条件和本轮感知优先规则。早期失败记录保留于下方数据链接。
  • 真实音频流程暴露迟到开场事件/自身工具回执引起重复介绍；修正事件时序与安静状态判定。第二次音频测试还修正了尚未真正瞄准沙盘就开始测试的用例设置，最后实测通过。
  • 模型玻璃罩保留顶面与四壁，移除与底座顶面重合的底面；这次复核没有重合三角面，三档画质各 12 帧，浏览器无脚本错误。

实际覆盖边界

  • 真实模型用实际引擎快照，并在标注处加入场景对话、关系或事件；不是 21 条全程实机游玩路线。
  • find_path 查询由独立无窗口真实引擎计算；未复原任意历史下全部结构改造。
  • 浏览器流程拦截决策响应以确定性验证执行和状态，真实模型另测；语音测试回放真实模型句子并调用真实阿里云 TTS。
  • 六个结算页中，失忆门与逃离实际触发；另四个直接触发结局。加速结局流程关闭语音。
  • TTS 为一次真实时钟测量；未测网络中断、所有长句和用户声卡。无窗口浏览器静音，未抢占用户鼠标。
  • 软件 GPU 三档 36 帧验证底板几何与控制台错误，不能代替所有硬件和驱动。
  • LLM 输出仍有随机性；规则层保护旧响应、静默、感知边界和关键关系事实，不保证每局措辞完全相同。
