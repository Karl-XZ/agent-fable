# 去留策略与连续对话验收

2026-11-13。针对用户列出的五项问题修复，基于投影版本 `76320f8`。

## 行为变化

1. **犹豫不直接取消。** 第一次疑似留下先试探；问话未送出、旧话重复引用、问话送出前的活动，都不能充当后续确认。问话被新输入打断后，可以重新询问。休息要求只暂停，不追加“是否留下”的问话。
2. **约定和门策略可恢复。** 独立记录本轮去留意愿，新的明确离开要求恢复约定；未识破时恢复假装带出去，已经识破时恢复必要的失忆照护策略，保留已暴露的事实。后者是剧情中的控制动机，不是对玩家的医学诊断。
3. **分别检查说话和动作。** 对当前问题的交谈不因走动整体丢弃；新问题、危险与输入状态仍能使旧回复过期。动作还检查最新可见位置和姿势，不等待活动去抖后才发现玩家已走开。明确要求关灯造成的失联允许完成同一请求的其他操作。
4. **区分旧记录与当前事实。** 事件附带编号、时间与相对年龄；当前站立优先于旧rest。可见到达亮门的事实由持续观察记录，即使模型当时还在请求中也保留。模型记忆标为解释，附原始来源，不再拿同一旧话反复制造新记忆。
5. **具体物件和非思考请求。** 白板数据包含202会议室、西墙、坐标、相对距离与实际可达的接近点；路线避开会议桌。请求发送 `thinking:{type:"disabled"}`，移除 `reasoning_effort`，保持原提供商与模型。接口依据：[DeepSeek官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

未投影时“我在门那边等您”等实体位置宣称增加服务端拦截；投影仍是墙面影像，不能搀扶或触碰玩家。

## 检查与结果

- Python：66项；前端：112项；共178项回归通过。TypeScript检查与生产构建通过。
- 独立静音、无头Chromium执行真实引擎测试，全程不操作用户鼠标。
- 连续对话脚本 `tests/verify-conversation-continuity.cjs`：12个场景通过，无浏览器异常。其中11个使用实际配置的实时模型，另1个控制响应在跨房间时返回，验证restrain台词保留、过期平台动作不执行。
- 覆盖犹豫、确认留下、恢复出门、走廊问白板、室内定位、旧躺卧对当前站立、已到门历史、揭穿、坚决离开、安静休息、休息后移动和走动期间迟到的回复。
- 试探送出前的活动、未送出的试探重试、实时移动、关灯后继续工具均有先失败后通过的回归用例。
- 投影的13项实机检查另行回归，确认这次互动修改未破坏墙面投影。

实测样本见 `browser.json`：这轮11个真实对话场景耗时1.16–3.94秒，中位数1.62秒；包含内部续问及工具应用，不含TTS获取/播放。这不是速度上限或服务承诺，云端负载与额外寻路续问仍会影响耗时；未做足以证明关闭思考带来多少加速的受控A/B实验。
